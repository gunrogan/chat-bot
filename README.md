# 🎓 Учебные чат-боты: «Допиши бота сам»

Веб-приложение с игровыми чат-ботами, в котором **ученик 12–13 лет сам дописывает
логику общения** с выбранным персонажем. Готовые темы, красивый интерфейс и
общий клиент уже собраны — остаётся написать «мозг» бота на Python.

> **Главная задача проекта:** научить подростков основам программирования через
> практику — писать логику, обрабатывать текст, хранить состояние игры и
> принимать решения по `if` / `elif` / `else`, циклам, словарям и спискам.

## 1. О проекте

### 1.1. Что это такое

Небольшое Django-приложение, в котором на одной странице работает игровой
чат-бот. У каждого бота — свой персонаж, своя «легенда», свой набор команд и
своя шкала прогресса (XP).

Готовые темы:

| Ключ `variant` | Персонаж | Оформление | Шкала прогресса |
|---|---|---|---|
| `robot` | 🤖 Робот-Учёный (демо-референс) | оранжево-синий | Уровень · XP |
| `magic` | 🧙 Профессор Мерлин, Академия магии | фиолетово-янтарный | Ранг · очки магии |
| `ship` | 🖥️ Бортовой компьютер корабля «Звезда-12» | тёмно-синий | Система · единицы энергии |
| `detective` | 🕵️ Агент Сова, детективное агентство | песочно-янтарный | Ранг · очки интуиции |
| `trader` | 🦝 Енот-Купец, лавка | изумрудный | Капитал · монеты |
| `survival` | 🧭 Инструктор по выживанию, необитаемый остров | лаймовый | День · дни выживания |
| `dungeon` | 🐲 Хранитель подземелья «Вечное Пламя» | каменно-янтарный | Уровень · очки опыта |

### 1.2. Цели обучения

В процессе работы ученик осваивает:

* **Работа с текстом:** `strip()`, `lower()`, поиск подстроки через `in`,
  разделение строки через `split()`.
* **Принятие решений:** `if` / `elif` / `else`, сравнение строк, проверка
  вхождений.
* **Данные:** списки, словари, вложенные структуры, срезы.
* **Состояние игры:** переменные уровня модуля, счётчики очков, здоровье,
  инвентарь — «память» бота между сообщениями.
* **Генерация случайности:** `random.choice`, `random.randint`,
  `random.shuffle` — чтобы игрок не получал одинаковые ответы.
* **Функции:** написание собственных функций с понятными именами и
  документацией.
* **Работа в команде:** чтение чужого кода, аккуратное форматирование,
  комментарии, следование ТЗ.

### 1.3. Что уже сделано за ученика

* Все 7 страниц-тем с адаптивной вёрсткой (Tailwind CSS через CDN), анимациями,
  «печатает…», конфетти и шкалой XP.
* Общий клиент чата `templates/chat/_chat_client.html` — отправка сообщений,
  показ ответа, начисление XP.
* Демо-бот `build_reply_demo()` — **работающий пример** хорошего стиля
  (поиск по ключевым словам, заготовки ответов, `random.choice`).
* Маршрутизация, чтение конфига, обработка ошибок API.

### 1.4. Что нужно сделать ученику

Реализовать 6 функций-заглушек в блоке **«НОВЫЕ ВАРИАНТЫ ОФОРМЛЕНИЯ»** файла
`chat_app/views.py`. Сейчас каждая из них выглядит так:

```python
def build_reply_magic(message: str) -> str:
    # TODO(магический помощник): волшебник в академии магии — задания,
    # загадки, проверка ответов, очки опыта и уровни.
    return 'ПРИВЕТ'
```

Строка `'ПРИВЕТ'` — это заглушка. Пока она не заменена, выбранный бот на
странице отвечает только «ПРИВЕТ» на любой вопрос.

> ⚠️ **Важно:** функцию `build_reply_demo` не трогаем — это рабочий
> демо-эталон, всегда доступный по адресу `/demo/`.

## 2. Быстрый старт

### 2.1. Требования

* **Python 3.10+** (проверено на 3.11 и 3.14).
* **Django 5.2** (ставится из `requirements.txt`).
* Интернет нужен только для загрузки шрифтов Google Fonts и Tailwind CDN.
* База данных — SQLite (`db.sqlite3`), устанавливать ничего не нужно.

### 2.2. Создание виртуального окружения

В проекте **уже есть** папка `.venv`, но она создана на Windows
(внутри лежат `Scripts/python.exe` и пути вида `C:\Users\...`). На Linux/macOS
её нужно пересоздать.

**Windows (PowerShell / cmd):**

```bash
cd C:\путь\к\Chat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

**Linux / macOS:**

```bash
cd /путь/к/Chat
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Если `python3 -m venv` ругается на отсутствие `ensurepip`, поставьте пакет
`python3-venv` (Debian/Ubuntu: `sudo apt install python3-venv`).

Проверка, что всё установилось:

```bash
python -c "import django; print(django.get_version())"
# 5.2.18
```

### 2.3. Подготовка базы данных

```bash
python manage.py migrate
```

Команда создаст/обновит `db.sqlite3`. Без неё не будет работать
`/admin/`, но сам чат запустится и без базы.

### 2.4. Запуск сервера

```bash
python manage.py runserver 8000
```

* Страница активного бота: <http://127.0.0.1:8000/>
* Демо-бот «Робот-Учёный» (всегда работает): <http://127.0.0.1:8000/demo/>
* Админка Django: <http://127.0.0.1:8000/admin/>

Остановить сервер: `Ctrl + C` в терминале.

> 🌐 **Доступ из локальной сети (класс, компьютер учителя).**
> Запустите `python manage.py runserver 0.0.0.0:8000` и добавьте в
> `Chat/settings.py` адрес компьютера: `ALLOWED_HOSTS = ['localhost', '127.0.0.1', '192.168.1.10']`.
> Узнать адрес: `ip addr` (Linux) или `ipconfig` (Windows).

### 2.5. Полезные команды

| Команда | Что делает |

| `python manage.py runserver` | Запустить сервер разработки |
| `python manage.py runserver 8001` | Запустить на другом порту |

### 2.6. Быстрая проверка API (без браузера)

Django защищает POST-запросы проверкой CSRF-токена, поэтому сначала нужно
получить cookie `csrftoken` с любой страницы сайта:

```bash
# 1) получаем cookie csrftoken
curl -s -c cookies.txt http://127.0.0.1:8000/ -o /dev/null

# 2) отправляем сообщение боту
curl -s -b cookies.txt \
     -X POST http://127.0.0.1:8000/api/chat/send/ \
     -H "Content-Type: application/json" \
     -H "X-CSRFToken: $(grep csrftoken cookies.txt | awk '{print $7}')" \
     -d '{"message": "Привет"}'
```

Ожидаемый ответ (после того как бот дописан):

```json
{"reply": "Текст ответа вашего бота"}
```

Если бот ещё не дописан, вместо нормального ответа придёт заглушка:

```json
{"reply": "ПРИВЕТ"}
```

> Без cookie `csrftoken` сервер вернёт `403 Forbidden` — это нормальная
> защита Django, а не ошибка проекта.

## 4. Настройка `config.json`

### 4.1. Где лежит файл

`config.json` находится **в корне проекта** (рядом с `manage.py`). Именно там
его ищет модуль `chat_app/config.py`:

```python
BASE_DIR = Path(__file__).resolve().parent.parent   # корень проекта
CONFIG_PATH = BASE_DIR / 'config.json'
```

### 4.2. Формат файла

```json
{
  "variant": "ship"
}
```

Файл — обычный JSON, в UTF-8, с одним обязательным ключом `variant`.

### 4.3. Набор параметров

| Параметр | Тип | Обязателен | Описание | Допустимые значения |
|---|---|---|---|---|
| `variant` | строка | нет (есть значение по умолчанию) | Какой бот показывается на главной странице `/` | `robot`, `magic`, `ship`, `detective`, `trader`, `survival`, `dungeon` |

Других параметров пока нет. Если позже понадобится, например, приветствие или
имя бота, ключи добавляются в этот же JSON-файл и читаются в
`chat_app/config.py`.

### 4.4. Что происходит при разных значениях

| `variant` | Главная страница `/` | API `POST /api/chat/send/` | Шаблон |
|---|---|---|---|
| `robot` | Робот-Учёный | `build_reply_demo()` | `templates/chat/robot.html` |
| `magic` | Академия Магии | `build_reply_magic()` | `templates/chat/magic.html` |
| `ship` | Борт корабля «Звезда-12» | `build_reply_ship()` | `templates/chat/ship.html` |
| `detective` | Детективное агентство | `build_reply_detective()` | `templates/chat/detective.html` |
| `trader` | Лавка Енота-Купца | `build_reply_trader()` | `templates/chat/trader.html` |
| `survival` | Необитаемый остров | `build_reply_survival()` | `templates/chat/survival.html` |
| `dungeon` | Подземелье Вечного Пламени | `build_reply_dungeon()` | `templates/chat/dungeon.html` |

### 4.5. Правила и «защита» от ошибок

Значение `variant` читается **один раз при запуске сервера** (в момент импорта
`chat_app.config`). Поэтому:

* после правки `config.json` сервер нужно **перезапустить** (`Ctrl + C`,
  затем `python manage.py runserver 8000`);
* значение приводится к нижнему регистру и обрезается от пробелов, поэтому
  `"Magic"`, `" magic "` и `"MAGIC"` работают одинаково;
* если файла нет, он битый (невалидный JSON) или в нём неизвестный вариант —
  приложение **не падает**, а использует значение по умолчанию
  `DEFAULT_VARIANT = 'magic'` (Академия Магии);
* `robot` в `config.json` — это тот же демо-бот «Робот-Учёный», что и на
  `/demo/`.

### 4.6. Как переключить тему (пошагово)

1. Откройте `config.json` в редакторе.
2. Замените значение `variant`:

```json
{ "variant": "detective" }
```

3. Перезапустите сервер.
4. Откройте <http://127.0.0.1:8000/> — теперь работает детективный бот.

## 5. Как устроен чат: страницы и API

### 5.1. Маршруты

| Адрес | Метод | Назначение | Обработчик |
|---|---|---|---|
| `/` | GET | Страница **активного** бота (из `config.json`) | `views.chat_page` |
| `/api/chat/send/` | POST | Отправка сообщения **активному** боту | `views.api_chat_send` |
| `/demo/` | GET | Демо-страница «Робот-Учёный» (всегда доступна) | `views.chat_page_demo` |
| `/api/chat/send_demo/` | POST | Отправка сообщения демо-боту | `views.api_chat_send_demo` |
| `/admin/` | GET | Админка Django | стандартная |

### 5.2. Формат запроса и ответа

**Запрос:**

```http
POST /api/chat/send/ HTTP/1.1
Content-Type: application/json
X-CSRFToken: <значение cookie csrftoken>

{"message": "Запусти двигатели!"}
```

**Успешный ответ (200):**

```json
{"reply": "Ответ бота"}
```

**Ошибки (400):**

```json
{"error": "Тело запроса должно быть валидным JSON"}
```

```json
{"error": "Сообщение не может быть пустым"}
```

### 5.3. Как работает отправка сообщения

```
Браузер                         Django
   │  POST /api/chat/send/  ──────►  api_chat_send()
   │  {"message": "..."}            │
   │                                ├─ _parse_message(): проверяет JSON и пустоту
   │                                ├─ REPLY_BUILDERS.get(ACTIVE_VARIANT)
   │                                └─ builder(message)  →  build_reply_*(message)
   │  ◄──────  {"reply": "..."}     │
   │  показать пузырь + конфетти +25 XP
```

Диспетчер `REPLY_BUILDERS` в `chat_app/views.py`:

```python
REPLY_BUILDERS = {
    'robot': build_reply_demo,
    'magic': build_reply_magic,
    'ship': build_reply_ship,
    'detective': build_reply_detective,
    'trader': build_reply_trader,
    'survival': build_reply_survival,
    'dungeon': build_reply_dungeon,
}
```

Если `ACTIVE_VARIANT` не найден в словаре (например, в `config.json` попали
новое имя), сработает запасной вариант — `build_reply_demo`.

### 5.4. Клиент на странице

Общий скрипт `templates/chat/_chat_client.html` (подключается во всех темах):

* берёт адрес API и оформление из `data-*` атрибутов `<body>`:
  `data-api-url`, `data-mascot`, `data-xp-name`, `data-level-name`,
  `data-bot-bubble`, `data-user-bubble`, `data-typing`, `data-confetti`;
* отправляет `fetch()` с JSON и заголовком `X-CSRFToken` (cookie `csrftoken`
  появляется благодаря `{% csrf_token %}` в шаблоне);
* показывает анимацию «бот печатает…», затем пузырь с ответом;
* начисляет **+25 XP** за каждый ответ и обновляет шкалу;
* запускает конфетти.

> 🎮 **Важно для ученика:** XP начисляется на стороне браузера, а состояние
> бота (очки, здоровье, инвентарь) нужно вести **внутри Python-кода** —
> в переменных уровня модуля.

### 5.5. Шкала прогресса в разных темах

| Тема | Название уровня | Название очков |
|---|---|---|
| Робот-Учёный | Уровень | XP |
| Академия магии | Ранг | очки магии |
| Корабль | Система | единицы энергии |
| Детектив | Ранг | очки интуиции |
| Торговец | Капитал | монеты |
| Выживание | День | дни выживания |
| Подземелье | Уровень | очки опыта |

## 6. 🎯 Задание: блок «НОВЫЕ ВАРИАНТЫ ОФОРМЛЕНИЯ»

### 6.1. Где именно работать

Файл **`chat_app/views.py`**, блок с комментарием:

```python
# ===========================================================================
# НОВЫЕ ВАРИАНТЫ ОФОРМЛЕНИЯ
# build_reply_* оставлены заглушкой «ПРИВЕТ» — код внутри НЕ реализован.
# ===========================================================================
def build_reply_magic(message: str) -> str:
    ...
```

Нужно реализовать **6 функций**:

| Функция | Тема | Персонаж |
|---|---|---|
| `build_reply_magic` | Академия магии | 🧙 профессор Мерлин |
| `build_reply_ship` | Космический корабль | 🖥️ бортовой компьютер |
| `build_reply_detective` | Детективное агентство | 🕵️ агент Сова |
| `build_reply_trader` | Лавка | 🦝 Енот-Купец |
| `build_reply_survival` | Необитаемый остров | 🧭 инструктор по выживанию |
| `build_reply_dungeon` | Подземелье | 🐲 Хранитель |

### 6.2. Общие правила для всех ботов

1. **Сигнатура не меняется:** `def build_reply_xxx(message: str) -> str:`
2. **Возвращается строка** — текст ответа, который увидит игрок.
3. **Сообщение нормализуется в начале:**

   ```python
   text = message.strip().lower()
   ```

4. **Никаких внешних сервисов и библиотек.** Только стандартный Python
   (`random` уже импортирован в `views.py`). Интернет, API, база данных,
   файлы — не нужны.
5. **Обязательно обработайте приветствие** (слова `привет`, `здравствуй`,
   `хай`, `hello`) и **незнакомый ввод** (ветка `else` в конце).
6. **Состояние игры** (очки, здоровье, день, инвентарь) храните в переменных
   **уровня модуля** — рядом с функцией, над ней. Пример:

   ```python
   MAGIC_XP = 0
   MAGIC_LEVEL = 1
   ```

   или в словаре:

   ```python
   MAGIC_STATE = {'xp': 0, 'level': 1, 'tasks_done': 0}
   ```

   ⚠️ Внутри функции переменная `x = 0` **обнулится** при каждом вызове —
   состояние не сохранится. Это важная часть задания!
7. **Используйте `random`** (`random.choice`, `random.randint`), чтобы ответы не
   были одинаковыми.
8. **Стиль кода:** отступ 4 пробела, `snake_case` для имён, комментарии
   объясняют *почему*, а не *что*.
9. **Не ломайте API:** функция всегда возвращает строку, даже при ошибке.
10. **Минимум 3–4 разных реакции** на команду и **минимум 5–8 ключевых
    слов**, иначе бот будет «глухим».

### 6.4. Как выглядит правильно реализованная функция

Ниже — **фрагмент-образец** (не готовое решение задания, а демонстрация
стиля). Свою версию пишите по аналогии.

```python
# Состояние живёт на уровне модуля — иначе сбросится при каждом вызове.
MAGIC_STATE = {'xp': 0, 'level': 1, 'riddle': None}


def build_reply_magic(message: str) -> str:
    """Волшебник Мерлин: задания, загадки, проверка знаний."""
    text = message.strip().lower()

    # 1. Приветствие
    if any(word in text for word in ('привет', 'здравствуй', 'хай', 'hello')):
        return (
            'Привет, юный волшебник! 🧙 Я профессор Мерлин. '
            'Спроси «загадка», «задание» или «проверь знания»!'
        )

    # 2. Загадка
    if 'загадк' in text:
        riddle, answer = random.choice(MAGIC_RIDDLES)
        MAGIC_STATE['riddle'] = answer          # запоминаем ответ
        return f'Загадка: {riddle} Отгадай! 🌀'

    # 3. Проверка ответа на последнюю загадку
    if MAGIC_STATE['riddle'] and MAGIC_STATE['riddle'] in text:
        MAGIC_STATE['xp'] += 25
        MAGIC_STATE['riddle'] = None
        return f'Верно! 🎉 Ты получаешь 25 очков магии. Всего: {MAGIC_STATE["xp"]}.'

    # 4. Задание
    if 'задани' in text:
        MAGIC_STATE['xp'] += 10
        return f'Твоё задание: {random.choice(MAGIC_TASKS)} (+10 очков магии)'

    # 5. Незнакомый ввод
    return 'Мерлин задумался 🤔 Скажи «помощь», чтобы узнать мои команды.'
```

**Что здесь важно:**

* `text = message.strip().lower()` — приводим к единому виду, чтобы
  «ПРИВЕТ» и «привет» попали в одну ветку;
* `any(word in text for word in (...))` — проверяем несколько ключевых слов
  одним условием;
* `random.choice(MAGIC_RIDDLES)` — случайный выбор;
* `MAGIC_STATE['riddle']` — память бота между сообщениями;
* `f'...'` — f-строки, чтобы подставлять числа и переменные в текст;
* последний `return` — «заглушка» для всего, что бот не понял.

## 10. Решение проблем

| Проблема | Причина | Что делать |
|---|---|---|
| `ModuleNotFoundError: No module named 'django'` | Не активировано виртуальное окружение | Активируйте `.venv` и выполните `pip install -r requirements.txt` |
| На странице стили «сломаны», нет цветов | Не загрузился Tailwind CDN | Нужен интернет или соберите Tailwind локально |
| Бот отвечает «ПРИВЕТ» на всё | Функция-заглушка не реализована | Допишите `build_reply_*` в `chat_app/views.py` |
| После правки `config.json` тема не сменилась | Конфиг читается при старте сервера | Перезапустите `runserver` |
| `DisallowedHost` в браузере | Нет адреса в `ALLOWED_HOSTS` | Добавьте адрес в `Chat/settings.py` |
| `400` при отправке сообщения | Тело запроса — не JSON или сообщение пустое | Проверьте формат: `{"message": "текст"}` |
| `403 Forbidden` при отправке сообщения | Не передан CSRF-токен | Загружайте страницу через сервер (не открывайте HTML-файл напрямую) и используйте `fetch`, а не `curl` без cookie |
| `404` на `/` | Нет шаблона `templates/chat/<variant>.html` | Проверьте значение `variant` в `config.json` |
| Изменения в `views.py` не видны | Сервер не перезапущен | `Ctrl + C` и снова `python manage.py runserver` |
| Ошибка `IndentationError` | Сбились отступы | Используйте 4 пробела, не табы |
| Ошибка `NameError: name '...' is not defined` | Опечатка или переменная объявлена ниже по файлу | Объявляйте константы **выше** функции |

**Полезно для отладки:**

* Тест функции без сервера — `python manage.py shell` (раздел 7, шаг 6).
* Проверить, что проект в порядке, — `python manage.py check`.
* Посмотреть, что реально приходит на сервер, — включите в `Chat/settings.py`
  `DEBUG = True` и смотрите подробный лог в терминале сервера.
* Напечатать значение словаря целиком — `print(состояние)` в `shell`.

## 11. Что менять не нужно

| Файл / функция | Почему не трогаем |
|---|---|
| `build_reply_demo` | Это рабочий эталон и демо-страница `/demo/` |
| `REPLY_BUILDERS` | Словарь-диспетчер, связывает тему с функцией |
| `chat_app/config.py` | Чтение конфига и список допустимых вариантов |
| `templates/chat/_chat_client.html` | Общий клиент: отправка, XP, конфетти |
| `templates/chat/_head.html`, `_styles.html` | Общие стили и подключение Tailwind |
| `Chat/settings.py` | Только если нужно разрешить другой хост |

Если ученик хочет **новую тему** (например, «пират»):

1. создать `templates/chat/pirate.html` (скопировав любую тему и поменяв
   тексты, эмодзи и `data-*` атрибуты);
2. добавить `build_reply_pirate` в `views.py`;
3. зарегистрировать в `REPLY_BUILDERS`: `'pirate': build_reply_pirate`;
4. добавить `'pirate'` в `VALID_VARIANTS` в `chat_app/config.py`;
5. указать `{"variant": "pirate"}` в `config.json`.

### 12.4. Шпаргалка «как добавить ключевое слово»

```python
# Одно слово
if 'топливо' in text:
    ...

# Несколько альтернатив
if any(word in text for word in ('топливо', 'бензин', 'горючее')):
    ...

# Целая фраза
if 'запусти двигатели' in text:
    ...

# Разбор фразы: первое слово — команда, остальное — аргумент
parts = text.split()
if parts and parts[0] == 'купи':
    товар = ' '.join(parts[1:])   # «купи зелье силы» -> «зелье силы»
```
